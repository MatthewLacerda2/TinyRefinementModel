## Notes

- **Do not use `checkpoints/best/`.** Its newest entry is opt step 24,385. It fires on
  `monitor.is_new_best` (`trm/train/trainer.py:434`), which tracks *windowed train CE*, not
  held-out val CE, and train CE is per-batch noisy enough to latch onto a lucky window. Val
  CE improved monotonically to the end, so **the latest rolling checkpoint is genuinely the
  best one**. This is the second run in a row where `best/` was stale — the July card flagged
  it too and it was never filed. Now filed.
- **The checkpoint is step 30,464, not the final step 30,520.** Checkpoints land every 64
  steps and the budget stop fell between two of them. 56 steps lost at a point where the
  cosine LR is effectively at its 1e-6 floor. Immaterial to the weights.
- **`git_dirty: true`.** The working tree carried one uncommitted change for the entire run —
  the `NUM_HEADS % NUM_GROUPS` assert in `trm/config.py`, captured in `worktree.patch` and
  archived beside the weights. The recipe is therefore *SHA + patch*, not SHA alone. Landed
  afterwards in PR #220 so the next card can cite a clean SHA.
- **What this run licenses.** It establishes that the pipeline can carry a model to the end
  of a multi-billion-token horizon unattended — the open infrastructure question since every
  prior base run died at opt step 1540 / 201.9M tokens
  (`docs/findings/2026-08-14-bfc-fragmentation-killed-every-base-run.md`, fixed in #162).
  This run went **20× further with zero OOM deaths.** It says nothing yet about whether depth
  recurrence works; that needs the yardstick and then a matched control.
- **Depth 4 and depth 8 are near-interchangeable** on the fixed prompt set — 7 of 8 prompts
  produced byte-identical completions at the final checkpoint. Motivation for #219.
- Supersedes `run_20260719_042625-refiner-base-v1.md` as champion (that one: val CE 4.7092 at
  147M tokens, ~27× less data).
